Unicode normalization and mixed-script character detection

NFC combines canonically equivalent characters where possible, while NFD decomposes them. The tool reports if your text already matches each form and offers an optional copy of NFC-normalized text without altering the original. A word mixing Latin with similar-looking Greek or Cyrillic characters may deserve review, but multilingual text is normal and this limited detector is not a comprehensive Unicode security or confusable-character scan.

Why are there different character counts?

A JavaScript string stores UTF-16 code units; a Unicode code point is a scalar value; and a grapheme cluster is the visible character a reader perceives. For instance, a family emoji can consist of several code points joined together. PostChars counts each measure separately.

UTF-8 bytes and hidden characters

UTF-8 uses between one and four bytes per Unicode scalar value. This inspector also flags a focused list of zero-width, directional and formatting characters that can make copied text unexpectedly hard to edit. The list is not an exhaustive Unicode security scan.

Common questions

Does it modify my text?

No. This is an inspection-only tool and never strips characters automatically.

Does an invisible character always mean malicious text?

No. Some scripts, emoji sequences and accessibility or typography workflows legitimately use formatting code points.

Hidden characters the inspector flags

The inspector lists the position and code point of invisible formatting characters, including the zero-width space (U+200B), zero-width non-joiner and joiner (U+200C, U+200D), word joiner (U+2060), byte order mark (U+FEFF), soft hyphen (U+00AD) and the bidirectional control characters (U+200E, U+200F, U+202A–U+202E, U+2066–U+2069). These often arrive with text copied from web pages, PDFs or chat apps and cause problems such as a password or coupon code that “looks right” but fails, a duplicate that is not detected, or a URL that breaks. Bidirectional controls deserve particular attention in source code, where they can make text display in a different order from how it is processed.

Normalization and lookalike letters

The same visible text can be stored in different ways: é as one precomposed code point (NFC) or as e plus a combining accent (NFD). Two strings that look identical may therefore fail an exact comparison. The inspector shows whether your text is already in NFC and NFD, and lets you copy an NFC-normalized version, which is the form most web content uses. It also flags single words that mix Latin, Greek and Cyrillic letters, such as a Cyrillic “а” inside an English word, a technique sometimes used in lookalike domain names and phishing.

Step by step

  1. Paste the text you want to inspect.
  2. Compare the four length measures with the limit you are trying to meet.
  3. Review any flagged hidden characters and mixed-script words.
  4. Copy the original or the NFC-normalized text. The inspector never changes your input on its own.

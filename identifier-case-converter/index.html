Convert identifier naming conventions

camelCase starts with lowercase, PascalCase capitalizes each word, snake_case separates with underscores, and kebab-case uses hyphens. CONSTANT_CASE uses uppercase letters and underscores.

What happens to acronyms?

The tool detects common boundaries such as HTTPResponse and first_name before converting. This simple tokenizer may not perfectly infer unusual acronyms or language-specific punctuation; inspect results before using them in source code.

How the converter splits words

Before converting, the tool breaks your input into words. It splits on spaces, hyphens and underscores, and at the boundary where a lowercase letter or digit is followed by a capital (orderTotal becomes “order total”). It also separates a run of capitals from a following capitalized word, so XMLHttpRequest becomes “xml http request” and getHTTPResponse becomes “get http response”. Text is normalized with Unicode NFKC first, which turns full-width letters into their ordinary forms.

Edge cases to review by hand

  • Acronyms. The converter treats an acronym as a word, so XMLHttpRequest becomes xmlHttpRequest in camelCase. Some style guides prefer xmlHTTPRequest or keep the original; follow your project's convention.
  • Numbers. Digits stay attached to the preceding letters: HTML5 parser becomes html5Parser and html5_parser.
  • Reserved words. A converted name can collide with a language keyword, such as class or default.
  • Non-ASCII letters. Accented letters are kept. Some languages and tools only allow ASCII identifiers.
